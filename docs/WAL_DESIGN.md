# kvDB 项目预写日志 (WAL) 设计文档

## 1. 概述 (Overview)

预写日志 (Write-Ahead Log, WAL) 是 `kvDB` 数据库实现持久性和原子性的核心组件。其基本原则是在任何数据被写入内存中的数据结构（如 MemTable）并最终持久化到 SSTable 之前，必须先将描述该操作的日志记录写入到磁盘上的 WAL 文件中。

这种机制确保了即使在写入过程中发生系统崩溃或断电，数据库在重启后也能通过重放 (Replay) WAL 文件来恢复到崩溃前的状态，从而防止数据丢失。

- **主要模块**: `kvdb::storage::Wal`, `kvdb::storage::WalRecord`
- **磁盘文件**: WAL 日志被保存在一个单独的文件中，通常位于 `data/wal/kvdb.wal`。

## 2. 核心组件 (Core Components)

### 2.1. `WalRecord`

`WalRecord` 是 WAL 中最基本的原子单元，它封装了一次数据库操作的所有信息。

- **主要属性**:
  - `op_type_`: 操作类型 (`PUT`, `REMOVE`, `CLEAR`)。
  - `key_`: 操作的键。
  - `value_`: 操作的值 (仅对 `PUT` 有意义)。
  - `sequence_number_`: 一个单调递增的64位无符号整数，作为操作的逻辑时间戳。
  - `checksum_`: 对数据负载计算出的 CRC32 校验和，用于验证记录的完整性。

### 2.2. `Wal`

`Wal` 类是 WAL 文件的管理器。它负责：

- **文件I/O**: 打开、关闭、读取和写入 `kvdb.wal` 文件。
- **记录追加**: 将 `WalRecord` 对象序列化为二进制格式并追加到文件末尾。
- **日志重放**: 在数据库启动时，从头读取 WAL 文件，并根据 `Manifest` 提供的检查点恢复 MemTable。
- **线程安全**: 内部使用 `std::mutex` 保护对文件的并发访问。

## 3. 磁盘格式 (On-Disk Format)

WAL 文件由一系列连续的 `WalRecord` 记录组成。每个记录都采用 **长度前缀 (Length-Prefixed)** 的二进制格式，以确保可以准确地从流中分离出单条记录，即使在发生部分写入时也能识别出损坏的记录。

**单条记录的精确布局如下:**

```
+------------------------+--------------------------+------------------------------------+
| 总长度 (Total Length)  | CRC32 校验和 (Checksum)  | 数据负载 (Payload)                 |
| (4 字节, uint32_t)     | (4 字节, uint32_t)       | (变长)                             |
+------------------------+--------------------------+------------------------------------+
```

- **总长度**: 记录了这条记录 **自身** 的总字节数（包含“总长度”字段本身）。
- **CRC32 校验和**: 这是对 **数据负载 (Payload)** 部分计算出的 CRC32 校验和，不包含长度和校验和字段本身。用于验证数据在读写过程中没有损坏。
- **数据负载**: 包含了操作的实际信息，其内部布局为：

  ```
  +--------------+-----------+-----------+-------------+-------------+-----------------+
  | 操作类型     | Key 长度  | Key 数据  | Value 长度  | Value 数据  | 序列号          |
  | (1 byte)     | (4 bytes) | (变长)    | (4 bytes)   | (变长)      | (8 bytes)       |
  +--------------+-----------+-----------+-------------+-------------+-----------------+
  ```

## 4. 工作流程 (Workflow)

### 4.1. 记录追加 (Append)

当执行一次写操作时（如 `db->put()`），流程如下：

1.  `Database` 类请求 `Wal` 类追加一条记录。
2.  `Wal` 类创建一个 `WalRecord` 对象，并为其分配一个新的、递增的 `sequence_number`。
3.  `WalRecord::serialize()` 方法被调用，它：
    a. 序列化 **数据负载**。
    b. 对序列化后的数据负载计算 CRC32 **校验和**。
    c. 将 `[总长度][CRC32][数据负载]` 组装成最终的二进制记录。
4.  `Wal` 类将这条二进制记录追加到 `kvdb.wal` 文件的末尾。
5.  调用 `file_.flush()` 确保操作系统将文件缓冲区的数据写入磁盘，保证持久性。

### 4.2. 数据库恢复 (Recovery)

当数据库启动时，`Database::recover()` 方法被调用，恢复流程如下：

1.  **加载 Manifest**: `Database` 首先加载 `Manifest` 文件，从中获取 `last_wal_sequence_number`。这个数字是最后一次成功将 MemTable 刷入 SSTable 时的检查点。
2.  **请求重放**: `Database` 调用 `wal_->replay()` 方法，并提供一个回调函数（Lambda）。
3.  **过滤并重放**: `Wal::readNextRecord()` 从 `kvdb.wal` 文件开头逐条读取记录。
    - 对于每一条成功读取并校验通过的记录，`Database` 的回调函数会执行一个关键检查：
      ```cpp
      if (record.getSequenceNumber() <= last_wal_sequence_number) {
          // 跳过此记录
      } else {
          // 应用此记录到内存中的 MemTable
      }
      ```
    - 这个检查至关重要，它避免了将已经存在于 SSTable 中的数据重复加载到内存中，极大地提高了启动效率。
4.  **完成恢复**: 当所有相关日志被重放后，内存中的 MemTable 就恢复到了系统崩溃前的状态。`Wal` 内部的序列号计数器也会更新为日志中的最高序号，以保证后续操作的连续性。
