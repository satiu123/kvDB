# SSTable (Sorted String Table) 文件格式技术文档

### 1. 概述

SSTable 是一种为大规模键值存储设计的、不可变的、有序的磁盘文件格式。其核心设计目标是优化写入吞吐量和提供高效的读取性能。这里的“不可变”特性意味着一个 SSTable 文件一旦被写入，就永远不会被修改，任何更新或删除都将记录在新的 SSTable 文件中。

我们的 SSTable 格式主要由四个部分组成：**数据块 (Data Blocks)**、**布隆过滤器块 (Bloom Filter Block)**、**索引块 (Index Block)** 和 **文件尾注 (Footer)**。

### 2. 文件逻辑结构

一个 SSTable 文件的整体布局如下所示。文件从数据块开始，接着是布隆过滤器和索引块，最后以一个固定大小的尾注结束。

```
+----------------------------------+
|         Data Block 1             |
+----------------------------------+
|         Data Block 2             |
+----------------------------------+
|               ...                |
+----------------------------------+
|         Data Block N             |
+----------------------------------+
|        Bloom Filter Block        |
+----------------------------------+
|           Index Block            |
+----------------------------------+
|             Footer               |  (固定大小, 40 字节)
+----------------------------------+
```

### 3. 组件详解

#### 3.1. 数据块 (Data Block)

数据块是键值对的基本存储单元。我们将多个连续的、有序的键值对打包进一个数据块，以减少元数据开销和 I/O 次数。

*   **默认大小**: 一个数据块在被写入磁盘前，其在内存中的大小阈值通常设为 4KB (可配置)。
*   **内部记录格式**: 每个键值对在数据块内按以下格式紧密排列：
    ```
    +------------------+------------------+-------------------+-------------------+
    | key_length (u32) |   key_data (bytes) | value_length (u32)|  value_data (bytes) |
    +------------------+------------------+-------------------+-------------------+
    ```
    *   `key_length`: 4 字节无符号整数，表示键的长度。
    *   `key_data`: 实际的键数据，长度由 `key_length` 决定。
    *   `value_length`: 4 字节无符号整数，表示值的长度。
    *   `value_data`: 实际的值数据，长度由 `value_length` 决定。

*   **特性**:
    *   **有序性**: 块内的所有记录都是根据键（Key）严格有序的。
    *   **独立性**: 每个数据块都可以被独立地读取和解析。

#### 3.2. 布隆过滤器块 (Bloom Filter Block)

布隆过滤器是一种概率性数据结构，用于快速判断一个元素**是否可能存在**于集合中。

*   **功能**: 在 SSTable 中，布隆过滤器用于在访问磁盘上的数据块之前，快速过滤掉那些**肯定不存在**的键查询。如果布隆过滤器判断一个键不存在，那么就可以确定它不在这个 SSTable 中，从而避免了昂贵的磁盘 I/O。
*   **格式**: 布隆过滤器块包含两个部分：
    1.  **位图 (Bitmap)**: 存储布隆过滤器的位数组。
    2.  **元数据**: 包括哈希函数的数量、位图大小等信息，用于在加载时重构过滤器。

#### 3.3. 索引块 (Index Block)

索引块是 SSTable 实现快速查找的关键。它不包含任何实际的值数据，而是作为数据块的稀疏索引（Sparse Index）。

*   **功能**: 索引块存储了每个数据块的“路标”。通过在内存中加载这一个块，就可以快速定位任何一个键（Key）可能存在于哪个数据块中，从而避免了全文件扫描。
*   **内部记录格式**: 索引块由一系列索引记录组成，每个记录对应一个数据块：
    ```
    +---------------------+---------------------+----------------------+--------------------+
    | last_key_length(u32)| last_key_data(bytes)| block_offset (u64)   | block_size (u64)   |
    +---------------------+---------------------+----------------------+--------------------+
    ```
    *   `last_key_length` / `last_key_data`: 对应数据块中的**最后一个键**。在查找时，我们可以通过比较目标键和索引中的 `last_key` 来确定目标键应该落在哪两个“路标”之间。
    *   `block_offset`: 8 字节无符号整数，表示该数据块在 SSTable 文件中的起始偏移量（从文件头开始计算）。
    *   `block_size`: 8 字节无符号整数，表示该数据块的字节大小。

#### 3.4. 尾注 (Footer)

尾注是 SSTable 文件的元数据核心，它像一本书的目录页码一样，告诉我们去哪里找到索引和布隆过滤器。

*   **位置与大小**: 尾注位于整个文件的**最末端**，并且拥有**固定的 40 字节大小**。这使得读取程序可以轻松地从文件末尾读取固定字节数来定位它。
*   **内部格式**:
    ```
    +---------------------------+-------------------------+-----------------------------+---------------------------+---------------------+
    | index_block_offset (u64)  | index_block_size (u64)| bloom_filter_offset (u64) | bloom_filter_size (u64) |    magic (u64)      |
    +---------------------------+-------------------------+-----------------------------+---------------------------+---------------------+
    ```
    *   `index_block_offset`: 8 字节，索引块在文件中的起始偏移量。
    *   `index_block_size`: 8 字节，索引块的总大小。
    *   `bloom_filter_offset`: 8 字节，布隆过滤器块的起始偏移量。
    *   `bloom_filter_size`: 8 字节，布隆过滤器块的总大小。
    *   `magic`: 8 字节的魔数（在我们的实现中是 `0x4B56444253535441`，即 "KVDB_SSTA" 的 ASCII 码），用于快速校验文件类型和完整性。

### 4. 读取流程示例（包含块缓存）

当需要从 SSTable 中查找一个键（例如 `my_key`）时，一个高效的实现会结合使用**块缓存**来最小化磁盘I/O和CPU解析开销。流程如下：

1.  **（首次）加载元数据**: 首次打开SSTable时，读取并解析 Footer、布隆过滤器和索引块，并将它们保留在内存中。

2.  **检查布隆过滤器**: 使用内存中的布隆过滤器检查 `my_key`。如果结果为“不存在”，则直接返回 `null`，流程结束。

3.  **在索引块中查找**: 如果布隆过滤器认为 `my_key` **可能存在**，则在内存中的索引块上执行二分查找，找到 `my_key` **可能**存在的数据块的元信息（偏移量 `offset` 和大小 `size`）。

4.  **检查块缓存**: 使用该数据块的唯一标识（例如 `文件路径 + offset`）查询全局的**块缓存**。
    *   **缓存命中 (Cache Hit)**: 如果在缓存中找到了一个**已解析**的数据块（例如，一个 `std::map`），则直接在这个内存中的 `map` 上执行最终的查找。如果找到，返回其值；否则，该键不存在。流程结束。
    *   **缓存未命中 (Cache Miss)**: 如果缓存中没有该块，则继续下一步。

5.  **从磁盘加载并解析**: 从该索引记录中获取 `block_offset` 和 `block_size`，从磁盘**一次性**读取对应的那一个数据块到内存。

6.  **解析并存入缓存**: 将刚刚从磁盘读取的原始数据块**完整解析一次**，构建出一个新的 `map` 来存储这个块的所有键值对。然后，将一个指向这个新 `map` 的共享指针存入块缓存中，以备后续使用。

7.  **在数据块中查找**: 在刚刚创建的 `map` 中查找 `my_key`，并返回其值。如果遍历完整个块都没有找到，则说明该键在整个 SSTable 文件中不存在。
